## Аналіз GIL та моделей конкурентності

1. **Потоки (Threads з увімкненим GIL):** 
   Не дали прискорення (10.60s проти 10.63s у серійному режимі), оскільки Global Interpreter Lock (GIL) дозволяє виконувати Python-байткод лише одному потоку в конкретний момент часу. Потоки просто стояли в черзі.

2. **Процеси (Processes):** 
   На малому корпусі (802 документи) виявилися повільнішими (13.91s) через значні накладні витрати на запуск 12 ізольованих інтерпретаторів за допомогою методу `spawn` та передачу даних через `pickle`. Водночас показник `CPU time` (5.25s) відображає роботу лише головного процесу, тоді як дочірні воркери виконували обчислення паралельно.

3. **Вільний від GIL Python (3.13t із `-X gil=0`):** 
   Запуск у 12 потоків на експериментальній збірці без GIL довів наявність реального паралелізму: сумарний процесорний час (`CPU time` = 13.47s) перевищив реальний час за настінним годинником (`Wall time` = 12.30s), що підтверджує паралельне виконання інструкцій на кількох ядрах.

4. **Закон Амдала:** 
   Етап злиття результатів (`merge`) є послідовною операцією (~0.6–0.8s) і створює математичну межу максимального прискорення системи незалежно від кількості доданих ядер.

## Встановлення та використання

```bash
# Встановлення інструмента локально
uv tool install .

# Побудова індексу (з підтримкою вибору воркерів та екзекюторів)
findex index data --out index.bin --workers 12 --executor processes

# Пошук за запитом
findex search index.bin "python AND search" --scorer bm25

# Статистика індексу
findex stats index.bin
